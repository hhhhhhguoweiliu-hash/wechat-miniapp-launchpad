# 阶段⑥：调试、体验版、提审上线

## 1. 自测清单（提审前逐项过）

- [ ] 开发者工具编译 0 报错 0 警告（warning 也清掉）
- [ ] **真机预览**：模拟器 → 预览 → 微信扫码。重点验模拟器不支持的能力：加速度计、人脸检测、震动、性能
- [ ] 每个页面都进到、每个按钮都点过
- [ ] 杀掉小程序重进：持久化数据恢复正常
- [ ] 分享链路：onShareAppMessage 生效、路径有效
- [ ] 包体积 < 2MB（`du -sh`）
- [ ] 路径大小写与文件名完全一致（真机区分大小写，模拟器不区分——经典翻车点）
- [ ] 所有用了的能力都在 app.json 声明了 permission

## 2. 上传体验版

开发者工具 → 上传 → 填版本号（0.1.0 起步）和项目备注 → 上传。
然后去 mp 后台 → 管理 → 版本管理 → 把刚上传的版本设为**体验版** → 体验二维码发给朋友。

## 3. 隐私保护指引（不过不能提审）

mp 后台 → 设置 → 服务内容声明 → 用户隐私保护指引：

- 用到什么声明什么：相册（选照片）、摄像头（拍照）、麦克风（录音）等。
- 用途描述写人话："用于在游戏页面展示您的头像"。
- **只声明真实用到的**，多声明会被问，少声明会被驳回。
- 如果照片不存服务器（chooseMedia 临时路径），在隐私指引和页面 UI 里都写明"不上传、不保存"——是合规加分项也是产品卖点。

## 4. 提交审核

版本管理 → 开发版本 → 提交审核：

1. **选类目**：个人主体只显示开放的类目。娱乐工具常用"工具 > 信息查询"或"生活服务"等；选错类目是最常见驳回原因，拿不准就换相近的试。
2. 功能页面：选首页，配一两句话说明。
3. 测试账号：纯本地无登录的项目不需要。
4. 提交后 1~24 小时出结果（快的 1 小时内）。

## 5. 个人主体常见驳回原因与对策

| 驳回理由 | 对策 |
|---|---|
| 类目不符 | 换更泛的类目（如"工具"），页面文案避免敏感词 |
| 涉及社交/U社区 | 去掉用户发帖、评论、加好友等功能；单机娱乐不受影响 |
| 涉及酒精/医疗建议等 | 文案改成"娱乐搞笑，请勿模仿/未成年人禁止使用"，加免责声明弹窗 |
| 隐私指引不完整 | 按第 3 节补齐，声明与实际一致 |
| 页面空白/功能异常 | 审核用的是普通手机网络，确保无后端依赖也能跑通全流程 |

含酒、烟、赌元素的娱乐 App：核心玩法可以保留，但**文案和声明要摆正**：加"未成年人禁止使用""适度娱乐"提示，能显著降低驳回率。

## 6. 发布与迭代

- 审核通过 → 版本管理 → 发布 → 即刻全量。
- 迭代节奏：版本号语义化（0.1.0 → 0.2.0 → 1.0.0），每次上传写清楚改动点，审核描述里说明"本次更新内容"。
- 数据分析：mp 后台 → 统计，看访问/留存，指导下一步功能。

## 7. 时间预期（给用户的实话）

注册账号：当天；开发：看复杂度，AI 辅助下简单娱乐类 1~2 天；审核：几小时到 1 天；被驳回重来：+0.5~1 天。从零到上线顺利的话 **2~3 天**。
